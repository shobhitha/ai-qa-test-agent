## 4. OpenAI Python SDK

The project uses the official OpenAI Python library.

It is installed with:

```bash
pip install openai
```

and imported using:

```python
from openai import OpenAI
```

The SDK provides a Python interface for communicating with the OpenAI API. It handles much of the underlying API communication and provides typed request and response objects.

Conceptually:

```text
Our Python Application
        ↓
OpenAI Python SDK
        ↓
OpenAI REST API
        ↓
OpenAI Model
```

Using an SDK is preferable to manually constructing HTTP requests for this application because it provides a cleaner Python interface and handles API-specific details for us.

## 5. Loading the API Key

The API key is stored in `.env` rather than directly in the Python source code.

Example:

```text
OPENAI_API_KEY=your_actual_api_key
```

The application loads the environment variables using:

```python
from dotenv import load_dotenv

load_dotenv()
```

The key is then retrieved using:

```python
import os

api_key = os.getenv("OPENAI_API_KEY")
```

The application validates that the key exists:

```python
assert api_key, "OPENAI_API_KEY was not found."
```

### Why?

API credentials are sensitive information and should not be hardcoded into source code or committed to GitHub.

## 7. Sending a Request

The application sends a request using the Responses API:

```python
response = client.responses.create(
    model="gpt-5.6-luna",
    input="Give me 5 negative test cases for a login page."
)
```

The request contains two important pieces:

### Model

```python
model="gpt-5.6-luna"
```

This specifies which OpenAI model should process the request.

### Input

```python
input="Give me 5 negative test cases for a login page."
```

This is the instruction provided to the model.

---

## 8. Understanding the Response

The value returned by:

```python
client.responses.create(...)
```

is a structured response object.

It is not simply a string.

Conceptually:

```text
response
│
├── response information
├── model information
├── output
├── usage information
└── other response metadata
```

The OpenAI Python SDK exposes response objects with typed fields and helper functionality.

For this project, we currently only need the generated text.

---

## 9. Using `response.output_text`

The generated text can be accessed through:

```python
response.output_text
```

For example:

```python
print(response.output_text)
```

This gives us the text generated by the model without requiring us to manually navigate the complete response structure.

For the current phase, this is sufficient because our objective is to verify that the model can generate text.

## 10. Pytest Validation

The API call is implemented inside a Pytest test:

```python
def test_openai_generates_qa_response():
```

The test verifies that the API returned non-empty text:

```python
assert response.output_text, "The API returned empty output."
```

The complete test is:

```python
import os

from dotenv import load_dotenv
from openai import OpenAI


load_dotenv()


def test_openai_generates_qa_response():
    api_key = os.getenv("OPENAI_API_KEY")

    assert api_key, "OPENAI_API_KEY was not found."

    client = OpenAI(api_key=api_key)

    response = client.responses.create(
        model="gpt-5.6-luna",
        input="Give me 5 negative test cases for a login page."
    )

    assert response.output_text, "The API returned empty output."

    print("\nAI Response:")
    print(response.output_text)
```

## 14. Design Decisions

### Why use `.env`?

The API key is sensitive and should not be embedded directly in source code.

### Why use `.env.example`?

It communicates which environment variables are required without exposing the actual secret.

Example:

```text
OPENAI_API_KEY=
```

### Why use the OpenAI Python SDK?

The SDK provides a Python-friendly interface to the OpenAI API and avoids manually implementing HTTP communication.

### Why put the API call in `tests/`?

At this stage, the purpose of the code is to validate the API integration. It is therefore treated as an integration test.

Later, reusable application logic will move into `app/`, while `tests/` will contain automated tests for that application logic.

### Why not build the agent yet?

A direct LLM call is not the same as a complete AI agent.

At this stage:

```text
Input
  ↓
Prompt
  ↓
LLM
  ↓
Response
```

This is an LLM-powered application.

The agent architecture will be introduced in later phases.

## 16. Interview Preparation

### What is the OpenAI Python SDK?

> The OpenAI Python SDK is the official Python client library for interacting with the OpenAI API. It provides a Python interface for creating API requests and working with typed API responses.

### Why use an SDK instead of making HTTP requests directly?

> The SDK abstracts much of the lower-level API communication and provides a convenient Python interface, typed request parameters, and structured response objects.

### What is the purpose of the `OpenAI` client?

> The `OpenAI` client provides the interface through which the Python application communicates with OpenAI's API.

### What does this code do?

```python
client = OpenAI(api_key=api_key)
```

> It initializes the OpenAI client using the API credential loaded from the environment.

### What does this do?

```python
client.responses.create(...)
```

> It sends a request to the Responses API with the specified model and input.

### What is `response`?

> It is a structured response object returned by the API. It contains the model output and other response information.

### What is `response.output_text`?

> It is a convenient property provided by the SDK for accessing the generated textual output from the response.

### Is this an AI agent?

> Not yet. At this stage, it is an LLM-powered application that sends an input to a model and receives a response. The agent architecture will be introduced later with decision-making, tools, and workflow orchestration.
